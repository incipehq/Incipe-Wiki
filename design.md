# design.md — Incipe Wiki design elements, directory and specs

The site's own design reference: what the parts are, where they live, and the
specs for anything built on top of them. Read with `CLAUDE.md` (rules) and
[`design/workspace-ui-inventory.md`](design/workspace-ui-inventory.md) (what the
desktop app looks like, label by label).

**The rule above all:** the look is the Incipe Workspace design system, copied
verbatim into `src/styles/`. Build with its tokens and `inc-*` recipes first. A new
element is allowed only when no existing one fits, and it must be assembled from
tokens, never raw values. New elements are listed in §4 with what they borrow.

## 2. Tokens (from `src/styles/tokens/`)

Use the role, not the value.

| Family | Tokens | Use |
| --- | --- | --- |
| Ground | `--mask`, `--bg`, `--panel`, `--panel-2`, `--surface`, `--surface-raised`, `--surface-card` | Page, panes, cards, floating boxes |
| Ink | `--text`, `--text-strong`, `--text-muted`, `--text-faint`, `--text-accent`, `--text-invert` | Body, emphasis, secondary, hints, accent ink, ink on accent |
| Accent | `--signal`, `--signal-hi`, `--signal-lo`, `--signal-wash` | The one accent. Selection wash = `--signal-wash` |
| Status | `--ok`, `--warn`, `--danger`, `--info` (+ `-wash`) | Never change with the accent |
| Edges | `--border-hair` (0.5px hairline), `--border-soft`, `--edge-soft` | Hairline on a surface; a floating box takes `--edge-soft` |
| Shape | `--radius-1/2/3`, `--radius-pill` | One 6px radius for controls (`--radius-2`) |
| Space | `--space-1 … --space-24` | 4px scale |
| Type | `--font-ui`, `--font-mono`, `--text-small/body/h1/h2/h3`, `--weight-*`, `--tracking-*` | Mono only for code, buttons, machine strings |
| Motion | `--dur-1…4`, `--ease-out`, `--ease-mech`, `--press-dim` | Every press is `scale(0.98)` over `--dur-press` |
| Elevation | `--shadow-pop`, `--elev-1…3` | Popovers and lifted cards |

Dark is the default; `theme-light.css` re-maps the same names. Never branch on theme in
`wiki.css`; let the tokens do it.

## 4. New elements and their specs

### 4.1 `AppScreen` — annotated screenshot

Shows a piece of the Workspace app with numbered pins; each pin names a control in
the app's own words. Borrows the app's **guided tip** (its highlight ring around a
control plus a numbered step) — the one place the app itself points at its UI.

**Authoring** (in any `wiki/*.md`):

````md
```screen
image: /app-guide/top-bar.png
alt: The Incipe Workspace top bar
---
7.3, 50 | Switch project | Shows or hides the project pane.
74.7, 50 | Verify | Compiles your code without uploading it.
```
````

- Header lines `key: value` above `---`: `image` (path under `public/`), `alt`
  (required), optional `caption`.
- One pin per line: `x, y | Label | What it does` — `x`, `y` are **percent** of the
  image's width and height, at the centre of the control. Label is the on-screen
  label, exactly. Pins are numbered in line order.

**Anatomy**

| Part | Class | Spec |
| --- | --- | --- |
| Figure | `wk-screen` | Hairline box, `--radius-2`, `--panel-2` ground, `margin-bottom: --space-4`. Does not clip, so a badge may cross its edge |
| Frame | `wk-screen-frame` | Holds the image at its natural ratio; pins positioned absolutely in % |
| Pin | `wk-screen-pin` + `wk-screen-badge` | A hollow 26px ring (1.5px `--signal`) centred on the control, so the control stays visible; its number on a 15px `--signal` badge at the ring's top-right, `--text-invert` mono. `data-on`: 2px ring, `--signal-wash` fill and halo. Press `scale(0.98)`. 20px ring below 820px |
| Key | `wk-screen-key` | Ordered list under the image; two columns ≥ 820px, one below |
| Key row | `wk-screen-item inc-row` | Number chip + **label** + text. Active row = `inc-row--on` |
| Caption | `wk-screen-cap` | `--text-muted`, `--text-small` |

**Behaviour:** hover or focus a pin or a key row → both light up. Click a pin → its
row scrolls into view. ←/→ inside the figure step through pins. A missing image
renders a neutral frame (“Screenshot coming soon”) and keeps the key, so a page is
never broken by an absent file. Reduced motion: no transitions.

### 4.2 App guide page

A Wiki page with `kind: app`. The guide is a **staircase**: 15 steps, each ending one
level higher, the last one a finished build.

**Frontmatter**

| Key | Example | Note |
| --- | --- | --- |
| `title` | `Verify and flash` | Imperative or plain noun phrase, sentence case |
| `kind` | `app` | Groups it under *Workspace app* |
| `step` | `6` | Position on the staircase; shown as *Step 6 of 15* and in the rail |
| `order` | `206` | `200 + step` — keeps the guide after every other page in global order |
| `reads` | `Verify, Flash and the compile console` | One line for cards |
| `keywords` | `verify flash upload compile ram` | Search terms, include the app's labels |
| `summary` | one sentence | Page lede |

**Story line.** The first paragraph is the story: where the classroom climate
monitor is now. App pages render it muted with a hairline under it
(`.wk-page[data-kind='app']`); the design system sets `<em>` upright, so slant is
not available.

**Body template** — keep every section short:

```md
*Story line: one or two sentences on where the build is now.*

## <Do the thing>          ← numbered steps, app labels in **bold**
```screen …```               ← where a picture saves words

## You can now
- <new ability>
- <new ability>

**Next:** <one line on the next step and why it follows>.
```

Neighbours: Previous / Next stay inside the guide (`wikiNeighbours` keeps `app`
pages together); the last step has no Next.

## 5. Screenshot spec (app guide)

- **Build:** the signed release `Incipe.app`, never the development build (it shows
  dev-only items).
- **Account:** a demo account with no personal data. No real email, invoices or chat
  titles in frame.
- **Window:** 1440×900 (the app's default), Night mode, Copper accent, Archivo, Comfy.
- **Story state:** project `climate-reader`, the Temperature & humidity module on
  socket **L1**.
- **Crop** to the region the page talks about; whole-window shots only for the tour.
- **Files:** `public/app-guide/<region>.png` (or `.jpg` for photos of the 3D board),
  lowercase-hyphen names (`top-bar.png`, `panel-board.png`). Capture at 2× and keep
  each under ~300 KB.
- **Crop thin strips short.** A strip wider than ~8:1 (the full top bar) shrinks to
  nothing on a phone; crop to the part the page talks about.
- **Interim images:** until the clean retake, some images are cut from development
  build captures, with the chat body blurred where it showed internal text. They are
  listed in `public/app-guide/README.md` and must be replaced.

## 6. Writing voice (app guide)

- Second person, present tense. Short sentences. One idea per step.
- Quote the app's labels exactly, in **bold**: **Verify**, **Board · USB**,
  **Follow along**. Menu paths with ›: **Account menu › Settings**.
- Story in a sentence or two at the top of a page and in *You can now*; never in the
  middle of steps.
- No fluff: no “simply”, “just”, “easy”, no marketing.
- Never invent an `incipe.*` function; link the sensor page instead.
